# LinkedIn: open-source-licenses-explained

## Post 1: native text

Sell the company or raise money, and someone will ask for a list of every open source package your software uses, with its license.

A typical web app pulls in hundreds. Most of those licenses ask very little. MIT and Apache 2.0 let you use the code in a closed commercial product if you keep the copyright notice.

A few ask more. Distribute software built on GPL code, as a desktop program or a device, and you have to make your source available under the same license. Code that only runs on your own servers generally doesn't count.

The AGPL closes that gap by treating network use as distribution. Change AGPL code and offer it over the web, and your changed source has to be available to its users. In a web app, it's the license to check first.

(General information from a software team, not legal advice.)

Licenses also come up in a big customer's procurement questionnaire. If a clinic commissions a patient portal and later licenses it to other clinics, code that was harmless in one private system now ships to other organizations.

This week, ask your developers for a tool-generated list of your dependencies and their licenses. If something needs replacing, now is when there's time to do it.

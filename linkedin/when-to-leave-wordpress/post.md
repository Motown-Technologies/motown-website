# LinkedIn: when-to-leave-wordpress

## Post 1: native text

Leave WordPress when keeping the site alive takes more of your team's time than writing for it.

On first calls we hear the same things: a dozen plugins waiting on updates with nobody sure which one breaks the site, bots hammering the admin login all day, slow pages nobody has explained, and a theme only the original developer understands.

If none of that sounds like your site, stay put. A migration is real work, and a site with a few plugins and fast pages on a phone is doing its job.

If it does sound familiar, you still might not need to replace the editor. An endoscopy center we worked with ran its site on WordPress. Staff liked editing in it, and nobody liked how it loaded for patients. So WordPress stayed as the back office, and the public pages are now built ahead of time from its content. Patients never touch WordPress, and if it has a bad day, only staff notice.

That route adds a build process someone has to maintain, so have the people who publish try the workflow first. Then decide who runs the forms, newsletter signups and analytics afterward, and write down every old URL and where it should go.

This week, list the problems you actually want to solve. If the list is short, fix the site you have.

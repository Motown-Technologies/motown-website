# LinkedIn: what-to-own-when-a-contractor-builds-your-software

## Post 1: native text

Before a contractor writes any code for you, set up the accounts in your company's name and give them access.

Most ownership problems start in week one, when the quickest way to begin is for the developer to use accounts they already have. Nobody notices until the relationship ends or an investor asks who owns the code.

What your company should own:

• The copyright. Paying for software doesn't automatically give it to you. Contractor work usually needs a signed IP assignment clause, covering any subcontractors too.
• The repository, in your organization, with the full history.
• The cloud and hosting accounts, billed to your card, with the contractor as a user you can remove.
• The domain, registered in your name. Your email probably depends on it.
• Payment, email and app store accounts, with keys kept in a password manager you control.
• Documentation: how to run it, deploy it, and where each secret lives.

A simple test for the last one: could an engineer you hire next month pick it up without calling the contractor?

If you aren't sure who holds the keys to software you've already paid for, it's worth finding out now.

# LinkedIn: what-to-own-when-a-contractor-builds-your-software

## Post 1: native text

Before a contractor writes any code for you, set up the accounts in your company's name and give them access you can take away later.

Most ownership problems start in week one, when it's quickest for the developer to use their own accounts. Nobody notices until the relationship ends, a payment's disputed, or an investor asks who owns the code.

Start with copyright, since paying for software doesn't automatically make it yours. Under US law, commissioned work only counts as "work made for hire" if it fits one of nine listed categories and both sides sign an agreement saying so. Custom software often doesn't, so development contracts usually include a clause assigning the IP to you. Check yours has one, covers subcontractors and is signed, and have a lawyer review the contract.

The rest is mostly accounts:

• The code repository, in your company's GitHub or GitLab organization. A zip of the finished code leaves out the history your next engineer needs.
• Cloud and hosting, billed to your card, with the contractor as a removable user.
• The domain, registered to your company. Your email probably depends on it.
• Payment, email and app store accounts in your name, with keys in a password manager you control.

Then documentation: how to run it on a new machine, deploy a change, and find each secret. Could next month's new engineer set it up without calling the contractor?
